# タイマー機能：確認結果と修正計画

## 1. タイマーの進行表示（右下ボタンの時間が見づらい）

### 現状
- **場所**: `lib/features/main_tab/main_tab_screen.dart` の `_TimerRoundButton`
- 稼働中は **60×60** の円形ボタン内に、**fontSize: 11** で `formattedTime`（例: 01:30）を表示
- 円形プログレス（残り時間のゲージ）の上にテキストが重なっており、サイズが小さく読みづらい

### 修正方針
- **時間表示を優先して見やすくする**
  - フォントサイズを **18〜20** 程度に拡大（タブレットではさらに大きく）
  - 必要に応じてボタンサイズを **64〜72** に少し拡大するか、時間だけをやや大きくしつつ円形は維持
- **レイアウト**
  - 時間とアイコン（再生/一時停止）を分けず、**時間のみ**を中央に大きく表示（稼働中はアイコンを小さく横に寄せるか、時間の下に補助表示）
  - または「時間を上段・アイコンを下段」の2行にして、時間のフォントを 18〜20 に固定
- **コントラスト**
  - `theme.colorScheme.onPrimary` のままでも可。必要なら `FontWeight.w800` やわずかなシャドウで視認性を向上

### 作業対象ファイル
- `lib/features/main_tab/main_tab_screen.dart`（`_TimerRoundButton` 内の `Text` と `SizedBox`）

## 2. デザインとカスタム設定

### 2(a) タイマー設定画面のデザイン刷新

**「タイマー設定画面」の解釈**:  
- **A) タイマー終了時の通知設定**（`timer_notification_settings_screen.dart`：バイブ・音のON/OFF等）  
- **B) タイマー本体のモーダル**（`timer_mini_widget.dart` の `TimerModalContent`：時間表示・開始/一時停止・プリセット・カスタム時間）

両方とも「古い」「デザイン性に優れていない」とみなして、**B) タイマーモーダル**を中心に、必要なら **A) 通知設定画面**もスタイリッシュに整える想定で計画します。

#### 現状（TimerModalContent）
- 白背景・グレー枠・青/オレンジの丸ボタン
- 「Quick Start」＋プリセット4つ、「Custom Time」＋分/秒入力＋Set の2ブロック構成
- 全体的にフラットで情報が並んでいるだけ

#### 修正方針（スタイリッシュ・かっこいい）
- **テーマ連携**: `Theme.of(context).colorScheme` を利用し、ダークモードでも崩れないようにする
- **ビジュアル**
  - メインの時間表示エリアを「時計風」や「カード風」にし、影・角丸・グラデーション（控えめ）で立体感を出す
  - プリセットはチップ/ピル型にして、選択状態を色と太さではっきり区別
  - 閉じるボタンは「枠線＋テキスト」で統一感を出す（現状の OutlinedButton を活かしつつスタイル調整）
- **余白・タイポグラフィ**
  - セクション間のスペースをやや広めにし、見出しを少し大きくして階層を明確に
- **通知設定画面（A）**
  - カード型のスイッチ/ラジオで、セクション分けを明確に
  - 既存の `BannerAdWidget` は維持しつつ、上側のコンテンツを整理

#### 作業対象ファイル
- `lib/features/workout_input/widgets/timer_mini_widget.dart`（`TimerModalContent`）
- 必要に応じて `lib/features/settings/screens/timer_notification_settings_screen.dart`

### 2(b) カスタムセット → 「時間を直接編集」に変更

#### 現状
- モーダル内に **「Quick Start」**（60s / 90s / 2min / 3min）と、**「Custom Time」**（分・秒の2つの TextField ＋「Set」ボタン）が**別枠**で存在
- 任意の時間にしたい場合は、下の Custom Time で分・秒を入力して「Set」を押す必要がある

#### 修正方針
- **メインの時間表示（大きな 00:00）を、停止中は「直接編集可能」にする**
  - 停止中：時間表示をタップすると、その部分が **分・秒を編集できる入力欄**に切り替わる（インライン編集）
  - または、時間表示の直下に常に「分」「秒」の小さな入力欄を置き、変更したら即タイマー値に反映（プリセットと同等の扱い）
- **「Custom Time」専用ブロックは廃止**
  - プリセットは「その時間にセットする」ショートカットとして維持
  - 任意の時間は「メインの時間を直接編集」で設定できるようにする
- **挙動**
  - 編集可能なのは**タイマー停止時のみ**
  - 分・秒を変更したら `timerNotifier.setTime(totalSeconds)` と `reset()`（または setTime のみ）で反映し、プリセットと同様「次回 Start でその時間で動く」ようにする

#### 作業対象ファイル
- `lib/features/workout_input/widgets/timer_mini_widget.dart`
  - メインの時間表示を「表示モード」と「編集モード」で切り替える
  - 編集モードでは現在の `_minutesController` / `_secondsController` の考え方を、**メイン表示の直下またはインライン**に移す
  - 「Custom Time」の Row（分・秒＋Set ボタン）は削除し、代わりにメイン時間タップで編集可能にする（またはメイン時間下にコンパクトな分・秒入力をつける）

## 3. 通知機能（バックグラウンドで「タイマーが終了しました」）

### 現状
- **アプリがフォアグラウンド**でタイマーが 0 になると、`TimerNotifier._tick()` で `hasFinished: true` になり、`main.dart` または `timer_mini_widget.dart` の `_showGlobalTimerFinishedNotification` / `_showTimerFinishedNotification` が実行される  
  → バイブ・音（`TimerNotificationService.play`）＋「Rest Complete!」ダイアログが表示される。
- **アプリがバックグラウンド**のときは、**タイマーのカウントは止まらない**（実時間ベースで `_computeRemaining()` が復帰時に計算される）が、**アプリがバックグラウンドにある「その瞬間」にシステム通知（プッシュ）を出す処理はない**。
- 使用パッケージ: `audioplayers`（音）、`HapticFeedback`（バイブ）のみ。**`flutter_local_notifications` 等のローカル通知は未使用**。
- そのため、**アプリを開いていない状態でタイマーが終了した場合、画面上に「タイマーが終了しました」のような通知は出ていない**。ユーザーが再度アプリを開くと、復帰時に `hasFinished == true` となり、その時点でダイアログと音・バイブが鳴る。

### 結論
- **「アプリをバックグラウンドで開いていない状態で終了したときに『タイマーが終了しました』という通知が来る」仕様は、現状では実装されていない。**
- 実現するには、**ローカル通知**（例: `flutter_local_notifications`）の導入が必要。

### 修正方針（実装する場合）
1. **`flutter_local_notifications` を追加**
   - タイマー **開始時**に、**終了予定時刻（startedAt + initialSeconds）**で1件のローカル通知をスケジュールする。
2. **タイマー終了時刻の計算**
   - `TimerNotifier.start()` 内で、`startedAt` と `_initialSeconds` から終了時刻を計算し、通知プラグインの「指定時刻に1回表示」API で登録する。
3. **通知文言**
   - 日本語: 「タイマーが終了しました」
   - 英語: “Timer ended” など（l10n 化推奨）。
4. **キャンセル**
   - ユーザーが一時停止・リセット・停止したら、スケジュールした通知をキャンセルする。
5. **バックグラウンド制約**
   - iOS: 通知権限のリクエストと、必要に応じて Background Modes の説明。
   - Android: 通知チャンネル作成（例: 「タイマー」チャンネル）、必要なら `exact alarm` または `schedule` の利用。

### 作業対象
- `pubspec.yaml`: `flutter_local_notifications` 追加
- 新規: 通知スケジュール／キャンセルを行うサービス（例: `lib/services/timer_local_notification_service.dart`）
- `lib/providers/timer_provider.dart`: `start()` でスケジュール、`pause()` / `reset()` / `stop()` でキャンセル
- `main.dart`: アプリ起動時の通知初期化・権限リクエスト
- iOS/Android の権限・チャンネル設定（必要に応じて既存の `timer_notification_settings_screen` に「通知をオンにしてください」の案内を追加）

## 実装順序の提案

| 順番 | 項目 | 内容 | 依存 |
|------|------|------|------|
| 1 | 1. 進行表示の見やすさ | 右下ボタンの時間フォント拡大・レイアウト調整 | なし |
| 2 | 2(b) カスタム→直接編集 | メイン時間を停止時に直接編集可能にし、Custom Time ブロック廃止 | なし |
| 3 | 2(a) タイマーモーダルデザイン | スタイリッシュ化（テーマ・カード・チップ等） | 2(b) と同時でも可 |
| 4 | 2(a) 通知設定画面デザイン | 必要ならカード型等に整理 | なし |
| 5 | 3. バックグラウンド通知 | flutter_local_notifications 導入・スケジュール/キャンセル・文言 | 1〜4 と独立 |

1・2・3 はユーザー体感が大きいため優先し、3（通知）はパッケージ追加とプラットフォーム設定が必要なため別フェーズにすると進めやすいです。
