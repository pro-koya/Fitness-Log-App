# Liftly 改善計画（辛口レビューに基づく）

辛口レビュー（`APP_REVIEW_辛口レビュー.md`）の指摘を、**優先度と実施順**で整理した改善計画。目標は「初回体験60%・D7継続20%・100ユーザー獲得」に届けること。

**追記**：以下の2点を計画に組み込み済み。① **ヘッダのボタンをフッターに** — スマホで操作しやすいよう主要導線（記録・履歴・設定）をボトムナビに移す（P1-4）。② **デザインの質感向上** — シンプルさを保ちつつ、余白・立体感・軽いガラス表現で「使っていて気持ちの良い」デザインにする（P1-6）。

---

## 優先度の考え方

| 優先度       | 意味                                           | 目安     |
| ------------ | ---------------------------------------------- | -------- |
| **P0** | ストア公開前に対応したい（品質・一貫性の土台） | 1〜2週間 |
| **P1** | 公開直後〜数週間でやりたい（差別化・体感）     | 2〜4週間 |
| **P2** | 余裕ができたら（中長期の強化）                 | 1〜3ヶ月 |

---

**目的**：READMEの「i18n 必ずリソース化」を満たし、どの言語でも一貫したメッセージにする。エラー時に技術用語を見せず信頼感を出す。

- **追加したいキー例**：`welcomeMessage`（既存）, `initialSetupLanguageLabel`, `initialSetupWeightLabel`, `initialSetupDistanceLabel`, `initialSetupStartButton` 等。既存の `welcomeMessage` があれば流用。

## P1：差別化の可視化と「最速」の体感

**目的**：「次のセットを最速で記録」が初見・初回で伝わるようにする。

### P1-1 ホームまたはチュートリアルに差別化メッセージを追加

| 項目                   | 内容                                                                                                                                                                                           |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 方針                   | ホームの「開始/再開」付近か、チュートリアルのツールチップに、短い一文を追加する。                                                                                                              |
| メッセージ例（日本語） | 「前回の記録は1タップでコピー」「セット間はタイマーでこのアプリだけで完結」                                                                                                                    |
| メッセージ例（英語）   | “Copy last set in one tap.” / “Rest timer built in—no app switching.”                                                                                                                     |
| 作業                   | 上記を l10n キー（例：`homeDifferentiatorCopy`, `homeDifferentiatorTimer`）で追加し、ホームのサブテキストまたはチュートリアル step の説明に表示。デザインは控えめ（1行テキスト程度）でよい |
| 確認                   | 初回利用の流れで「速さ・前回コピー・タイマー」のいずれかが言葉で触れられていること                                                                                                             |

**参照**：`lib/features/home/home_screen.dart`、`lib/features/tutorial/`（`TutorialStep` のメッセージ定義）

### P1-2 入力画面の空状態に短い励まし

### P1-3 ホームの「今日やること」を前面に（任意・軽い見た目調整）

| 項目     | 内容                                                                                                                                              |

## P1：ナビゲーションの見直し（ヘッダ → フッター）

**目的**：よく使う操作を**親指が届きやすいフッター**に寄せ、スマホでの操作しやすさと「2タップ以内」を両立する。現状は設定・全記録・種目一覧・メモ検索・履歴・タイマーがすべてヘッダ（AppBar）に集まっており、片手操作・README の「親指ゾーン」と矛盾しやすい。

### P1-4 フッター（ボトムナビ）の導入とヘッダの整理

| 項目    | 内容                                                                                                                                                                                                                                                                                                                                            |
| ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 方針    | **主要な導線（記録・履歴・設定）をフッターのボトムナビに移す**。サブ機能（種目一覧・メモ検索・全記録・タイマー）は履歴タブ内やホームのショートカットから開く形にし、ヘッダのアイコン過多を解消する。                                                                                                                                      |
| 選択肢A | **ボトムナビを導入**：「ホーム（記録）」「履歴」「設定」の 3 タブ。ホームで「開始/再開」＋最近の記録、履歴でカレンダー・全記録・種目一覧・メモ検索への導線、設定は現状の設定画面。`MaterialApp` の `home` をタブホルダー（例：`Scaffold` + `BottomNavigationBar`）に変更。                                                        |
| 選択肢B | **まずホームにショートカットのみ**：ボトムナビは行わず、ホームに「履歴」「種目」「メモ検索」等のリンク/ボタンを追加してタップ数を減らす。ヘッダは現状のまま。                                                                                                                                                                             |
| 推奨    | **A（ボトムナビ導入）を P1 で実装する**。スマホで操作しやすい「フッターに主要ボタンを配置する」という要望に直接応えられ、競合アプリとも揃う。B は A の前段階として「ホームにショートカットを足す」だけでも可。                                                                                                                            |
| 作業    | ① ルートをタブホルダーに変更（ホーム・履歴・設定の 3 画面をタブで切り替え）。② 各タブの内容は既存の `HomeScreen`・履歴系・`SettingsScreen` を流用。③ 履歴タブでは「カレンダー」「全記録」「種目一覧」「メモ検索」への導線を配置。④ ヘッダのアイコンは、各タブ内で必要なものだけ残す（例：ホームのタイマー、設定の AppBar はそのまま）。 |
| 確認    | ホーム・履歴・設定がフッターの 3 タップで切り替えられ、親指で届きやすいこと。ホームから「今日の履歴を開く」「種目一覧を開く」が 2 タップ以内になること。                                                                                                                                                                                        |

**参照**：`lib/features/home/home_screen.dart`、`lib/main.dart`（`MaterialApp` の `home` をタブホルダーに変更）、`lib/features/history/history_screen.dart`

## P1：デザインの質感向上（「気持ちの良い」デザイン）

**目的**：シンプルさは保ちつつ、ユーザーが使っていて**気持ちの良い**見た目・体感にし、ストアや初見でのインパクトを少し上げる。現状はフラットで装飾が少なく「普通のアプリ」に見えやすい。

### P1-6 デザインの質感向上（余白・立体感・軽いガラス表現）

| 項目   | 内容                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 指摘   | デザインがシンプルすぎてインパクトが薄い。iOS のガラスのような、使っていて気持ちの良いデザインに寄せたい。                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| 方針   | **「速さ・見やすさ」を損なわない範囲**で、余白・タイポグラフィ・カードの立体感を整え、必要に応じて**ナビやカードに軽いガラス表現**（半透明・ぼかし）を入れる。入力画面は視認性を最優先し、装飾は控えめにする。                                                                                                                                                                                                                                                                                                                                              |
| 作業案 | ①**余白・タイポ**：フォントサイズ・行間・パディングを少し見直し、読みやすさと上質さを出す。② **カードの立体感**：ホーム・履歴のカードに影や角丸を少し効かせ、タップ領域が分かりやすくする。③ **軽いガラス表現**：ボトムナビのバー、モーダルや一部カードに、半透明＋ぼかし（`BackdropFilter` 等）を**控えめに**適用。iOS のコントロールセンター風の質感を参考にしつつ、パフォーマンスと Android での見え方も確認する。④ **色のアクセント**：開始ボタン・記録完了など重要な操作にテーマ色を効かせ、他は控えめにして視線誘導を明確に。 |
| 注意   | ぼかし・半透明は負荷やプラットフォーム差が出やすいため、**入力画面のセット行やフォームには使わない**。ナビ・ヘッダ・カードの背景など一部に限定する。                                                                                                                                                                                                                                                                                                                                                                                                              |
| 確認   | 見た目の「質感」が上がり、かつ記録入力の見やすさ・速さが維持されていること。                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |

**参照**：`lib/utils/theme_generator.dart`、`lib/data/models/preset_theme.dart`、`lib/features/home/home_screen.dart`、ボトムナビ導入後のナビ用ウィジェット

## P2：中長期の強化（余裕ができたら）

### P2-1 広告配置の見直し

- **指摘**：記録入力中・記録完了直後に広告を出さないと、READMEの「記録を邪魔しない」に合う。
- **作業**：`BannerAdWidget` を表示している画面一覧を確認し、**ワークアウト入力画面・ワークアウト完了モーダル直後の画面**ではバナーを出さない（または遅延表示）ようにする。

### P2-2 ストア用コピー・スクショの準備

- **指摘**：アプリ内で「速さ・前回コピー・タイマー」を語っていないと、ストアでも伝えにくい。
- **作業**：P1-1 でアプリ内に差別化メッセージを入れたうえで、ストア用に「前回1タップでコピー」「セット間タイマーでアプリ内完結」等の短い説明文と、それに合うスクショ（入力画面・前回コピー・タイマー）を用意する（アプリ外の作業）。

### P2-3 Pro の追加ベネフィット（機能）

- **指摘**：Pro の価値が「同期＋広告削除」だけだと紹介しづらい。
- **作業**：種目別目標・週次サマリ・エクスポート強化など、**一つ**追加ベネフィットを決め、設計・実装する。スコープが大きいため P2 で検討でよい。

### P2-4 タブ内の導線・レイアウトの調整（P1-4 実施後）

- P1-4 でボトムナビを導入したあと、履歴タブ内で「全記録」「種目一覧」「メモ検索」への導線が分かりやすいか、アイコンやラベルの配置を調整する。必要に応じてタイマーへのアクセス（ホーム以外からの起動）を整理する。

## 実施順序の提案

1. **P0 を一通り完了**（文言統一・エラー表示）→ ストア申請前の品質底上げ。
2. **P1-1, P1-2**（差別化メッセージ・空状態の励まし）→ 初回体験と「最速」の体感。
3. **P1-5**（Pro の一文）→ 紹介・ストア文案と合わせて短時間で効く。
4. **P1-4**（フッターにボトムナビを導入）→ 主要操作を親指ゾーンに移し、ヘッダのアイコン過多を解消。
5. **P1-6**（デザインの質感向上）→ 余白・立体感・軽いガラス表現で「気持ちの良い」見た目に。P1-4 でナビが決まってからナビのガラス表現を当てると効率的。
6. **P1-3**（ホームの「今日やること」強調）→ 見た目の微調整。
7. **P2** はストア公開後、フィードバックを見ながら順次。
