改善計画（IMPROVEMENT_PLAN_改善計画.md）の **P2：中長期の強化** について、現状の機能を把握したうえでの実装案です。

### 広告（BannerAdWidget）

|----------|------|------|
| ✅ 表示 | 設定（settings_screen） | スクロール内・保存バー上 |
| ✅ 表示 | 履歴（history_screen） | カレンダー・月間サマリ下 |
| ✅ 表示 | 体重（body_weight_screen） | グラフ・履歴下 |

| ✅ 表示 | バックアップ（backup_screen） | 設定サブ画面 |
| ✅ 表示 | 筋トレMemo取り込み（import_screen） | 設定サブ画面 |
| ✅ 表示 | タイマー通知設定（timer_notification_settings_screen） | 設定サブ画面 |

### ナビ・タブ（P1-4 実施済み）

- **フッター 5 タブ**：記録（Home）／履歴（History）／一覧（List）／体重（BodyWeight）／設定（Settings）。
- **一覧タブ**：種目一覧・全ての記録・メモ検索への導線（ListMenuTabScreen）。
- **履歴タブ**：カレンダー・月間サマリ・先月/今月/来月。上部の「全記録・種目・メモ検索」チップは削除済み。
- **タイマー**：右下固定の丸ボタン（MainTabScreen 全タブで表示）。

### Pro 機能（現状）

- **Pro 限定**：クラウド同期（canSync）、広告非表示。
- **Free でも利用可能**：履歴全件、グラフ、テーマ、バックアップ・復元、種目検索、タイマー通知など。

## P2-1 広告配置の見直し

**目的**：README の「記録を邪魔しない」に合わせ、記録入力中・記録完了直後には広告を出さない（または遅延表示）にする。

### 現状の整理

- 記録**入力中**：`workout_input_screen` には `BannerAdWidget` なし → **対応済み**。
- **記録完了直後**：完了モーダル → ホームに `pop`。ホームにも広告なし → **対応済み**。
- **追加で検討する点**：記録完了後に「最近の記録」からその日のトレーニングを開くと `workout_detail_screen` に遷移し、ここでは**バナーが表示される**。「記録完了直後」を「完了から一定時間以内」と広く解釈するなら、ここを遅延表示の対象にできる。

### 実装案

| 項目 | 内容 |
|------|------|
| 必須 | 入力画面・完了モーダル・ホームに広告を出さない → **現状で満たしているため変更不要**。 |
| 推奨（任意） | **記録詳細画面の広告を遅延表示**：`workout_detail_screen` を「記録完了から開いた直後」と判定できる場合（例：完了直後に `push` されたセッション ID が同じ）、バナーを一定時間（例：30 秒）遅延表示する。判定が複雑になる場合は、P2-1 は「現状のまま」としても README の趣旨は満たしている。 |
| 確認 | 記録入力〜完了〜ホームに戻るまで、どこにもバナーが表示されないことを手動確認する。 |

**結論**：最低限の要件は満たしている。余裕があれば「記録詳細の遅延表示」を追加検討。

## P2-2 ストア用コピー・スクショの準備

**目的**：P1-1 で入れた差別化メッセージ（前回コピー・タイマー等）を前提に、ストアで「速さ・前回コピー・タイマー」が伝わるコピーとスクショを用意する。

### 実装案（アプリ外作業）

| 項目 | 内容 |
|------|------|
| コピー | 「前回を 1 タップでコピー」「セット間タイマーでアプリ内完結」等の短い説明文をストア説明に記載。P1-1 の l10n キー（`homeDifferentiatorCopy` 等）やチュートリアル文言を流用可能。 |
| スクショ | ① ワークアウト入力画面（セット入力・前回コピーが分かる状態）、② タイマー（モーダルまたは右下ボタンの稼働中）、③ ホームの「開始/再開」または差別化メッセージ、の 3 枚を想定。 |
| 担当 | デザイン・マーケ担当。アプリ実装は不要（文言の参照用に l10n 一覧を渡すとよい）。 |

**結論**：アプリ内の実装タスクはなし。ストア申請前のタスクとしてドキュメント化しておく。

## P2-3 Pro の追加ベネフィット（機能）

**目的**：「同期＋広告削除」以外の、紹介しやすい Pro の価値を 1 つ追加する。

### 候補とスコープ

| 候補 | 内容 | スコープ目安 | 備考 |
|------|------|--------------|------|
| **A. 種目別目標** | 種目ごとに「目標重量・回数」を設定し、記録画面や種目別進捗で「目標まであと〇〇」等を表示。 | 中（目標 CRUD、進捗画面・入力画面との連携） | 成長実感と「Pro で目標管理」が結びつきやすい。 |
| **B. 週次サマリ** | 週単位のトレーニング回数・ボリューム・種目別サマリを 1 画面で表示。履歴タブまたは新タブに追加。 | 中（集計ロジック、新 UI、l10n） | 「週の振り返り」という明確なベネフィット。 |
| **C. エクスポート強化** | 現状のバックアップ（JSON/CSV）は Free でも利用可能。Pro 限定で「PDF レポート」「週次/月次レポートのエクスポート」等を追加。 | 小〜中（既存バックアップの拡張 or 新エクスポート画面） | 既存の backup_screen を拡張しやすい。 |

### 推奨

- **まず 1 つに絞る**：スコープと「人に勧める一言」のしやすさから、**B. 週次サマリ** または **A. 種目別目標** を推奨。
- **B**：既存の月間サマリ（履歴タブ）の延長で設計しやすく、「Pro で週の振り返りができる」と説明しやすい。
- **A**：既存の種目別進捗（exercise_progress）と相性が良く、「目標設定」は有料機能として分かりやすい。

### 実装の流れ（案）

1. **方針決定**：A/B/C のどれを Pro 追加ベネフィットとするか決定。
2. **設計**：データモデル（目標テーブル or 週次集計の算出方法）、FeatureGate の新フラグ（例：`canAccessWeeklySummary`）、表示箇所を整理。
3. **実装**：Free では「Pro で利用可能」の案内＋Paywall 導線、Pro でフル機能。
4. **文言**：設定・Paywall の「Pro の価値」にその 1 文を追加（P1-5 と同様に l10n 化）。

**結論**：P2-3 は 1 機能に絞り、上記 A/B/C のいずれかで設計・実装する。スコープが大きいため、P2 の中で後回し or 段階的に進めてもよい。

## P2-4 タブ内の導線・レイアウトの調整（P1-4 実施後）

**目的**：フッター 5 タブ導入済みの前提で、履歴・一覧・他タブの導線とタイマーアクセスを整理し、迷いを減らす。

### 現状の整理

- **履歴タブ**：カレンダー＋月間サマリ。全記録・種目一覧・メモ検索は「一覧」タブに集約済み。
- **一覧タブ**：種目一覧・全ての記録・メモ検索の 3 導線がカードで表示。
- **タイマー**：全タブ共通で右下に固定。ホーム以外（履歴・一覧・体重・設定）からも起動可能。

### 実装案

| 項目 | 内容 |
|------|------|
| 導線の一貫性 | 「全記録を見る」は一覧タブの「全ての記録一覧」で到達。履歴タブから日付を選んでその日のサマリを開く流れは現状のまま。必要に応じて、履歴タブの空状態や月間サマリ付近に「一覧で全記録を見る」への短いリンクを追加（任意）。 |
| アイコン・ラベル | フッターの 5 タブのラベル（記録・履歴・一覧・体重・設定）は l10n 済み。アイコンは Material の標準で統一されている。特に違和感がなければ変更不要。 |
| タイマー | 全タブで同じ位置・同じ挙動で問題なし。履歴・体重・設定タブからもタイマーを開いて休息し、そのまま記録に戻る運用ができる。 |
| レイアウト微調整 | 履歴の月間サマリ・一覧タブのカード間余白・体重のグラフ高さなど、実機で見て「詰まりすぎ」「余白が不揃い」があれば軽く調整。大がかりな画面構成変更は不要。 |

**結論**：大きな変更は不要。ユーザーフィードバックや実機確認で気になった点だけ、余白・ラベル・1 リンク追加程度の微調整でよい。

## 実施順序の提案（P2 のみ）

1. **P2-1**：現状で要件は満たしているため、確認のみ。必要なら「記録詳細の遅延表示」を追加。
2. **P2-2**：ストア用コピー・スクショはアプリ外タスク。P1-1 完了後にストア申請タイミングで実施。
3. **P2-4**：タブ・導線・タイマーは現状で整理済み。フィードバックに応じて軽いレイアウト調整のみ。
4. **P2-3**：Pro 追加ベネフィットは設計・実装コストが大きいため、余裕ができたタイミングで 1 機能（週次サマリ or 種目別目標）を選んで実施。
