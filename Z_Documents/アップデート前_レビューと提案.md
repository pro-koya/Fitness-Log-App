# iOSアップデート前：全体レビューと提案

今回の修正（目標の分・秒/km、タイマーUI・通知・Quick Start、目標管理のFree開放）を踏まえ、**UI/UXの一貫性**と**獲得・継続**の観点でレビューし、アップデート前に検討したい点を提案する。

---

## 1. UI・UXが保たれているか

### 保たれている点

| 観点 | 状況 |
|------|------|
| **記録の速さ** | ホーム→記録開始は2タップ以内。セット入力・前回コピー・タイマー統合で「トレ中にこのアプリだけで完結」する流れは維持されている。 |
| **1画面1目的** | ホーム＝開始、入力＝積む、履歴＝見る、設定＝各種設定。タブ構成と導線は明確。 |
| **テーマ・デザイン** | Material 3・テーマ連携は維持。タイマーモーダル・通知設定・Quick Startはテーマ色を使い、ダークモードでも崩れない。 |
| **目標まわり** | 目標はFree/Pro共通で利用可能。時間は「分・秒」、距離は「km」で入力・表示され、単位の一貫性は取れている。 |
| **タイマー** | 右下ボタンの時間表示は見やすく、モーダルは2列Quick Start・直接編集・中央表示で整理されている。バックグラウンド通知で「タイマーが終了しました」が出る。 |

### 要確認・軽い改善候補

| 項目 | 内容 | 優先度 |
|------|------|--------|
| **タイマーまわりの文言** | モーダル内の「Rest Complete!」「Tap time to set」「Quick Start」「Close」が英語固定。`timerClose` は l10n にあるがモーダルでは未使用。日本語ユーザーには「休憩完了」「時間をタップして設定」「クイックスタート」「閉じる」など l10n 化があるとよい。 | 中（アップデート直後でも可） |
| **目標の Pro 案内文言** | `goalProUpsell`（「目標管理はProでご利用いただけます」）は、目標をFree開放したため**もう表示されない**。文言は残して問題ないが、将来的に他機能のPro案内に流用するか、arb の説明を「（未使用・他Pro案内用）」などに更新しておくと分かりやすい。 | 低 |
| **空状態・エラー** | IMPROVEMENT_PLAN の P0-4 の通り、エラー時は技術用語を出さず「読み込みに失敗しました。もう一度お試しください」＋リトライがあると信頼感が増す。既存の `errorLoadFailed` 等がどこまで使われているかは要確認。 | 中（時間があれば） |

**結論（UI/UX）**  
コンセプトの「最速で記録」「前回コピー」「タイマーが邪魔しない」は保たれており、今回の変更でタイマーと目標の使い勝手は向上している。致命的な不整合はなく、**タイマーの文言 l10n 化**を入れると、日本語ユーザー体験がさらに揃う。

## 2. ユーザーをしっかり獲得・維持できるアプリになっているか

### 獲得・維持に効いている点

| 要素 | 状況 |
|------|------|
| **無料で使える範囲** | 記録・履歴・種目別グラフ・タイマー・**目標管理**・テーマ・バックアップ等がFreeで使える。Proは同期・広告非表示に絞られており、「まず試す」ハードルが低い。 |
| **初回フロー** | 言語・単位→チュートリアル→最初の1本まで一本道。目標もFreeで使えるため、「目標を立ててから記録」という動機づけがしやすい。 |
| **継続の動機** | 種目別グラフ・目標達成・ストリーク・「今週達成した目標」等で成長実感が得られる。タイマー終了のバックグラウンド通知で、アプリを閉じていても休憩終了を逃しにくい。 |
| **差別化** | 前回1タップコピー・セット間タイマー統合・筋トレMemoインポート。READMEの「人に勧めやすい一言」に近い体験は揃っている。 |

### まだ弱い可能性がある点（辛口レビュー・改善計画と一致）

| 要素 | 内容 |
|------|------|
| **差別化の「見える化」** | ホームやチュートリアルに「前回を1タップでコピー」「セット間はタイマーで完結」などの**短い一文**があると、初見・ストア説明と一致しやすい（P1-1）。 |
| **ナビのタップ数** | 履歴・種目一覧・メモ検索等はタブ＋メニューから。よく使う操作が「2タップ以内」に収まっているかは、実際の利用で確認するとよい。 |
| **Proの価値** | 同期＋広告削除が中心。目標をFreeにした分、「Proでしかできないこと」をストア・paywallで**一言で伝える**文案があると、アップグレード理由が伝わりやすい。 |

**結論（獲得・維持）**  
Freeで使える範囲が広く、目標・タイマーが使いやすくなっているため、**試しやすさ**と**継続の理由**は強まっている。アップデート後は「初回体験成功率」「D7継続率」を簡単にでも見ると、次の改善の優先度が付けやすい。

## 3. 今回のアップデートで漏れていそうな機能・確認したい点

| 項目 | 内容 | 推奨 |
|------|------|------|
| **バージョン・ビルド番号** | `pubspec.yaml` の `version` をアップデート用に上げているか（例: 1.0.3+4 → 1.0.4+5）。 | アップデート前に必ず更新 |
| **ストア説明文** | 「目標管理はFreeで利用可能」「タイマー終了の通知（バックグラウンド対応）」など、今回の変更がストアに反映されていると、期待と実態が合う。 | 更新を推奨 |
| **権限・プライバシー** | タイマー通知でローカル通知を使用。iOSの「通知」権限説明が、App Storeのプライバシー／権限説明と矛盾していないか確認。 | 確認を推奨 |
| **目標の同期** | 目標（exercise_goals）がSupabase同期対象になっている場合、Proユーザーは他端末と目標が揃う。Freeはローカルのみで問題ない想定。 | 仕様確認のみ |
| **チュートリアル** | 目標がFreeになったため、チュートリアルや初回案内で「目標を設定できる」と触れると、利用開始の動機づけになる。 | 任意（文言追加で対応可） |

## 4. アップデート前に改善しておくとよい部分（提案）

### すぐできるもの（1日以内）

1. **タイマー関連の l10n**
   - キー例: `timerRestComplete`, `timerRestCompleteMessage`, `timerTapTimeToSet`, `timerQuickStart`, および既存の `timerClose` をモーダルで使用する。
   - 日本語: 「休憩完了」「休憩が終わりました。次のセットの準備はできましたか？」「時間をタップして設定」「クイックスタート」「閉じる」
   - これで日本語ユーザーでもタイマーまわりが統一される。

2. **バージョン表記**
   - `pubspec.yaml` の version を 1.0.4+5 などに更新し、必要なら「新機能・変更点」をストアやアプリ内の「バージョン情報」に1行ずつ書く。

3. **Pro案内の整合**
   - Paywallや設定の「Proでできること」から「目標管理」を外すか、「目標管理は無料で利用可能」と明記する。残す場合は「クラウド同期・広告非表示」が主であることが分かるようにする。

### 余裕があれば（数日）

4. **エラー表示の統一（P0-4）**
   - 起動失敗・データ取得エラーで、技術用語ではなく「読み込みに失敗しました。もう一度お試しください」＋リトライを表示する。既存の `errorLoadFailed` 等の利用状況を確認し、抜けている画面を揃える。

5. **ホームの差別化メッセージ（P1-1）**
   - ホームの「開始/再開」付近か、チュートリアルに「前回を1タップでコピー」「セット間はタイマーで完結」のような1行を追加する。既存の `homeDifferentiatorHint` がどこで使われているか確認し、未使用なら表示箇所を決める。
