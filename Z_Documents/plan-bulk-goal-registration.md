# 目標一括登録機能 — 実現可能性調査・方針

## 概要

目標一覧ページにボタンを配置し、**目標を立てたい種目をユーザーが複数選択**したうえで、一括で目標を設定する機能。  
設定する目標値は **過去のトレーニング履歴** と **登録されている体重** を目安に計算する。

---

## 方針（確定）

### 1. 操作方法

- ボタンタップ後、**種目選択画面（モーダルまたは別画面）** を表示する。
- 一覧には **複数選択用のチェックボックス** を付け、ユーザーが目標を立てたい種目にチェックを入れて選択する。
- 「一括で目標を設定」等の実行ボタンで、**選択された種目のみ** に対して目標値を計算・保存する。

### 2. 選択可能な種目の条件

- 一括登録で選択できる種目は、**過去にトレーニング履歴が 1 回以上ある種目だけ** を対象とする。
- 履歴がない種目は一覧に表示しない（または表示しても選択不可とする）。  
  → 目標値の計算根拠が「過去ベスト × 係数」のため、履歴がない種目は計算できないため。

---

## 方針の検討：この方針が最適か

| 観点 | 評価・理由 |
|------|------------|
| **ユーザーコントロール** | ✅ **最適**。ユーザーが「どの種目に目標を付けるか」を明示的に選べるため、意図しない上書きや、関係ない種目への目標付与を防げる。 |
| **データの一貫性** | ✅ **最適**。選択可能な種目を「履歴あり」に限定することで、全選択肢で「過去ベスト × 係数」が必ず計算でき、根拠のない目標値が混ざらない。 |
| **操作ステップ** | ✅ **許容範囲**。ボタン 1 回で全適用するより 1 ステップ増えるが、選択画面で「どれが候補か」が一目で分かり、誤操作を減らせる。 |
| **実装コスト** | ✅ **妥当**。「履歴あり種目一覧」を返す DAO メソッド 1 本と、チェックボックス付き一覧 UI の追加で実現可能。 |

**結論**: **この方針で進めるのが最適です。** 操作が明確で、対象が「履歴のある種目」に限定されるため計算ロジックが単純になり、意図しない上書きも防げます。

---

## 結論：**実現可能です**

必要なデータ・API は既にほぼ揃っており、**「履歴あり種目 ID 一覧」を返す DAO メソッドの追加** と、**チェックボックス付き種目選択 UI ＋ 一括計算ロジック** の追加で実装できます。

---

## 1. 対象データの有無

### 1.1 登録されている種目

| 項目 | 有無 | 取得方法 |
|------|------|----------|
| 種目一覧 | ✅ あり | `ExerciseMasterDao.getAllExercises()` |
| 種目ごとの記録タイプ | ✅ あり | `ExerciseMasterEntity.recordType`（`'reps'` / `'time'` / `'cardio'`） |

- **reps**: 目標タイプは `weight` / `reps` / `volume` のいずれか
- **time**: 目標タイプは `time`
- **cardio**: 目標タイプは `time` / `distance` のいずれか

### 1.2 選択可能な種目（履歴あり）

| 項目 | 有無 | 取得方法 |
|------|------|----------|
| 履歴が 1 回以上ある種目 ID 一覧 | ⚠️ 要追加 | **新規**: `SetRecordDao` または `ExerciseMasterDao` に「完了済みセッションに紐づく set_record が存在する exercise_id の一覧」を返すメソッドを追加する（例: `getExerciseIdsWithHistory()`）。 |
| 種目マスタ（名前・recordType） | ✅ あり | `ExerciseMasterDao.getExerciseById(id)` または、上記 ID 一覧に対し `getAllExercises()` の結果をフィルタ。 |

一括登録の**選択可能種目**は次のとおりです。

- **選択可能** = 過去にトレーニング履歴（完了済みセッション内の set_record）が 1 件以上ある種目だけ。
- 上記メソッドで取得した ID に対応する `ExerciseMasterEntity` を並べ、チェックボックス付き一覧で表示する。

### 1.3 過去のトレーニング履歴

| 項目 | 有無 | 取得方法 |
|------|------|----------|
| 種目ごとの過去ベスト（重量） | ✅ あり | `SetRecordDao.getBestValueForExercise(exerciseId, 'weight')` |
| 種目ごとの過去ベスト（回数） | ✅ あり | `getBestValueForExercise(exerciseId, 'reps')` |
| 種目ごとの過去ベスト（ボリューム） | ✅ あり | `getBestValueForExercise(exerciseId, 'volume')` |
| 種目ごとの過去ベスト（時間・秒） | ✅ あり | `getBestValueForExercise(exerciseId, 'time')` |
| 種目ごとの過去ベスト（距離・m） | ✅ あり | `getBestValueForExercise(exerciseId, 'distance')` |

- いずれも **完了済みセッション** のみ対象（既存実装で `ws.status = 'completed'`）。
- 履歴が無い種目は `null` が返る → その種目は「スキップ」または「体重のみで設定」（後述）で扱える。

### 1.4 登録されている体重

| 項目 | 有無 | 取得方法 |
|------|------|----------|
| 直近の体重 | ✅ あり | `BodyWeightDao.getLatest()` |
| 単位（kg/lb） | ✅ あり | `SettingsProvider` の `currentUnitProvider` |

- 体重が未登録の場合は `getLatest()` が `null` → 体重を使わない計算（履歴ベスト＋係数のみ）にフォールバック可能。

---

## 2. 目標値の計算方針（目安）

- 目標は **種目ごとの recordType** に合わせて **1 種目あたり 1 目標**（既存の `ExerciseGoalEntity` と同じ前提）。
- 既存の「1 種目 1 目標」の仕様上、reps 種目では weight / reps / volume のいずれか **1 つ** を選ぶ必要がある。一括の場合は **優先順位** を決める（例: 履歴があれば weight → volume → reps の順で採用し、最初にベストが取れたタイプで目標を立てる）。

### 2.0 係数（コース）の選択 — ユーザーが選べる（遊び心）

目標値は **過去ベスト × 係数** で計算する。係数は固定ではなく、**ユーザーが「コース」を選んで決める**。  
少し遊び心を持たせ、意欲に合わせて「どれくらい上を目指すか」を選べるようにする。

| コース名（ニュアンス） | 係数 | 想定イメージ |
|------------------------|------|--------------|
| 無理しない（健康維持など） | 1.1 倍 | 少しだけ上を目指す |
| しっかり伸ばす | 1.2 倍 | 程よくチャレンジ |
| ガッツリ追い込む | 1.3 倍 | しっかり高めの目標 |
| 目指せマッチョ | 1.5 倍 | かなり高めの目標 |

- **表示**: 種目選択画面の上部などに、上記 4 コースを **ラジオボタンまたはカード** で表示。1 つを選択必須とする。
- **文言**: 「初級」「中級」などの級名にはこだわらず、上記のような**ニュアンスが伝わる名前**（日本語・英語それぞれで）を付ける。例: 日本語「無理しない」「しっかり伸ばす」「ガッツリ追い込む」「目指せマッチョ」／英語 "Take it easy", "Step it up", "Push hard", "Go big" など。
- **既定値**: 未選択時は「しっかり伸ばす（1.2 倍）」を初期選択しておくと無難。

### 2.1 過去履歴ベストを使う場合（推奨）

| goalType | 計算例 | 備考 |
|----------|--------|------|
| weight | 過去最大重量 × **選択した係数** | kg で保存。単位は設定に従い表示時変換済み |
| reps | 過去最大回数 × **選択した係数** | 整数で保存 |
| volume | 過去最大 volume（weight_kg×reps）× **選択した係数** | kg で保存 |
| time | 過去最大 duration（秒）× **選択した係数** | 秒で保存 |
| distance | 過去最大 distance（m）× **選択した係数** | m で保存 |

係数はユーザーが選択したコース（1.1 / 1.2 / 1.3 / 1.5）で決まる。

### 2.2 体重を使う場合（オプション・将来拡張）

- 本機能では **選択可能な種目を「履歴あり」に限定** しているため、目標値は原則「過去ベスト × 係数」のみで計算する。
- 体重は、将来的に「体重の○倍を目標にする」等の補助や、目標難易度の目安に使う拡張が可能。現状の一括登録では必須ではない。

### 2.3 一括登録の流れ（確定）

1. **種目選択画面を開く**  
   目標一覧で「一括で目標を設定」ボタン → モーダルまたは新画面を表示。
2. **係数コースを選択**  
   画面上部に 4 コース（1.1 / 1.2 / 1.3 / 1.5 倍）を表示し、ユーザーが 1 つ選択。既定は「しっかり伸ばす（1.2 倍）」など。
3. **選択可能種目を表示**  
   `getExerciseIdsWithHistory()`（新規 DAO メソッド）で履歴ありの種目 ID を取得し、対応する `ExerciseMasterEntity` の一覧を **チェックボックス付き** で表示。初期状態は「全選択」または「未選択」のどちらかでよい。
4. **ユーザーが目標を付けたい種目にチェック**  
   複数選択可。「実行」または「一括で目標を設定」ボタンをタップ。
5. **確認**  
   「選択した ○ 種目に目標を設定します。既存の目標は上書きされます。よろしいですか？」等のダイアログで確認。
6. **計算・保存**  
   選択された種目についてのみ、**選択したコースの係数** を使って:
   - 単位を取得: `currentUnitProvider`。
   - 各種目: `recordType` に応じて goalType を決定 → `getBestValueForExercise(exerciseId, goalType)` でベスト取得 → `目標値 = ベスト × 係数` → `ExerciseGoalDao.upsert(...)` で保存。
   - （選択されている時点で履歴ありのため、ベストが null の種目は通常は発生しないが、万一のためスキップ処理を入れてよい。）
7. **完了**  
   `ref.invalidate(allGoalsListProvider)` で一覧を更新し、結果（○ 種目に目標を設定しました）を表示。

---

## 3. 既存コードとの整合

- **目標の保存**: `ExerciseGoalDao.upsert()` が既にあり、1 種目 1 目標の upsert が可能。
- **目標一覧**: `allGoalsListProvider` が `getAll()` と種目名・ベスト値を組み合わせているので、一括登録後はそのまま一覧に反映される。
- **種目削除**: 目標一覧では `getExerciseById(goal.exerciseId)` が null の種目は表示から外している。一括登録では「登録種目」のみ対象にするため、削除済み種目に誤って目標を付けないようにできる。
- **Pro 機能**: 目標機能は Pro のため、一括登録ボタンも `featureGateProvider.canAccessExerciseGoals` が true のときだけ表示する。

## 4. 追加・変更が必要なもの

| 種別 | 内容 |
|------|------|
| **DAO** | **必須**: 「完了済みセッションに紐づく set_record が 1 件以上存在する exercise_id の一覧」を返すメソッドを追加。例: `SetRecordDao.getExerciseIdsWithHistory()`。`workout_sessions.status = 'completed'` かつ `set_records` に存在する `exercise_id` を `DISTINCT` で返す。 |
| サービス/ロジック | 一括目標計算（provider 内またはサービス）。**ユーザーが選択した種目 ID のリスト**・**選択したコースの係数（1.1/1.2/1.3/1.5）**・単位を渡し、選択種目についてのみ `getBestValueForExercise` → 係数乗算 → `ExerciseGoalDao.upsert` を実行。 |
| **UI** | ① 目標一覧（`GoalListScreen`）に「一括で目標を設定」ボタン。② タップで **種目選択画面**（モーダルまたはルート）を表示：**係数コース**（4 択）を画面上部に配置 → **履歴あり種目だけ**をチェックボックス付きで一覧表示し、ユーザーが複数選択。③ 「一括で目標を設定」実行 → 確認ダイアログ → 実行 → 結果（○ 種目に目標を設定しました）を表示。 |
| 文言 | 多言語（app_ja.arb / app_en.arb）に「一括で目標を設定」「目標を立てたい種目を選択」「選択した ○ 種目に目標を設定します」に加え、**4 コースの表示名**（例: 健康増進 / コツコツと / ガッツリ追い込む / 目指せマッチョ、および英語）を追加。 |

## 5. 注意点・仕様の詰め方

1. **reps 種目の goalType 選び**: 一括では「weight / reps / volume のどれを採用するか」をルールで固定する。例: 履歴でベストが存在するものを優先（weight → volume → reps の順で試し、最初に null でないものを使う）。
2. **cardio の time / distance**: 同様に、両方試してベストがある方を採用する等のルールが必要。
3. **上書き**: 選択した種目に既存目標がある場合は上書きする。実行前に「既存の目標は上書きされます」旨を確認ダイアログで表示する。
4. **係数**: ユーザーが 4 コース（1.1 / 1.2 / 1.3 / 1.5 倍）から選択。既定は 1.2 倍（しっかり伸ばす）。
5. **期限・重要度**: 一括では `deadlineTs: null`, `priority: 2` で固定してよい（必要なら後から個別編集できる）。
6. **履歴あり 0 件**: 履歴がある種目が 1 つもいない場合は、ボタンタップ時に「目標の計算に使えるトレーニング履歴がまだありません」等のメッセージを表示し、種目選択画面は開かない。

---

## 6. まとめ

- **方針**: ボタン → **履歴あり種目だけ**を**チェックボックスで複数選択** → 選択した種目に対してのみ「過去ベスト × 係数」で目標を一括設定。この方針で UX・データ一貫性・実装コストのバランスが取れており最適。
- **データ**: 過去履歴（種目別ベスト）・体重・種目マスタは既存で取得可能。**「履歴あり種目 ID 一覧」を返す DAO メソッド 1 本**を追加すれば、選択可能種目の取得が完了する。
- **実装**: 上記 DAO ＋ チェックボックス付き種目選択 UI ＋ 一括計算・保存ロジック ＋ 確認・結果表示で実現可能。

次のステップは、「全選択／未選択の初期状態」を決めたうえで実装に進む。係数は 4 コースでユーザーが選択し、既定は 1.2 倍とする。
